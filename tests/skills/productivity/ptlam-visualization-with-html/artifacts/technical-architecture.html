Current reconstruction

One event, four ordered responsibilities

Read left to right on wide screens and top to bottom on narrow screens. Numbers preserve the same source order in both layouts.

  1. Step 1

    Ingress

    Accepts at most 240 events/s.

    Output: an immutable envelope with a synthetic event ID.

  2. Step 2

    Schema gate

    Checks exactly 12 required fields.

    Output: valid envelope or a quarantined rejection.

  3. Step 3

    Work queue

    Holds up to 3,600 envelopes.

    Output: one leased envelope with a 30 s lease.

  4. Step 4

    Worker and archive

    Writes one archive record, then acknowledges the lease.

    Output: an append-only record retained for 7 days.

Branch semantics

The schema gate owns the only split

Valid envelope

Relationship: schema gate → work queue. The worker may retry a leased event twice, but the event stays on the accepted path.

Terminal state: archived exactly once.

Invalid envelope

Relationship: schema gate → quarantine. The queue and worker never receive the rejected envelope.

Terminal state: quarantined with 1 reason code.

Proposed concept

Back-pressure preserves ownership

Queue above 80%
Ingress limits acceptance to 120 events/s until occupancy falls below 60%.
Lease not acknowledged in 30 s
The queue releases the same envelope for retry; the worker does not construct a replacement event.

Inference: keeping retry ownership in the queue avoids a second source of event identity. This inference follows from the synthetic contracts above; it is not a benchmark result.
